Typical setup

Bike diagnostic connector → verified bike-specific lead → protocol-matched interface → laptop running the desktop app. Some older three-pin leads need separate fused battery power and ground; verify the bike’s wiring first. Install the interface driver manually if needed, then select the actual serial port or CAN channel in Garage. Need an interface or bike-specific lead? Open the equipment guide.

For the source-listed Harley or ECU-only J1850 / HarleyDroid profile: enter the paired ELM327 serial port at 38400 baud and select read-only mode. Use the profile default first. The Honda CB500F DashBle entry is an explicit ECU-only option: its source does not specify the bike year or ECU and the integration is not hardware-tested. Auto waits 2.6 seconds after a failed fast attempt before slow init, so older ECUs do not mistake the fallback for the rest of a partial 5-baud address.

Enter a single Intrepid CAN network name such as HSCAN (or its documented CAN network ID) in Device above, and the exact device serial here. Direct neoVI requires python_ics installed in the Python environment; standard packaged builds do not include it. On Linux, an externally configured Intrepid SocketCAN interface can use the profile default instead. Adapter support does not establish ECU compatibility; this integration is synthetic-tested only. The backend sets the CAN bitrate on the selected hardware. Use only Intrepid hardware with libicsneo.

For classic-CAN SLCAN adapters, enter an explicit serial device above, such as COM5 or /dev/ttyACM0. The default serial speed is 115200; append @speed (e.g. COM5@115200) if needed. The adapter is configured for the selected ECU profile bitrate and transmits diagnostic requests. Synthetic-tested only; verify adapter wiring, firmware and bike compatibility. CAN-FD and automatic fitment are not provided.

Harley Delphi CAN identity research is available by source-listed vehicle or ECU-only override. This integration has synthetic tests only and may not work for a selected bike. It requires 500 kbit/s and fixed 0x7E0/0x7E8; enter an explicit SocketCAN channel (e.g. can0) or PCAN channel (e.g. PCAN_USBBUS1). This attempts tester-present, five raw identity DIDs and four raw source-observed DIDs; a response does not verify fitment and the source may require authentication. This Garage identity session does not provide ECU memory, security, or programming; the separate experimental Tools memory panel has a different workflow.

Generic OBD-II 11-bit CAN is an explicit ECU-only option, not a claim of compatibility with the selected motorcycle. It needs a compatible CAN interface and correctly wired adapter, 500 kbit/s and a physical OBD ECU ID pair; this integration has not been hardware-tested. It reads supported standard live PIDs and emission-related stored faults, not ECU memory.

Physical MIU G4 and 11MP sessions are blocked before the adapter opens: generic 0x7E0/0x7E8 IDs are not treated as Piaggio protocol evidence. The opt-in generic OBD profile accepts only physical OBD request/response pairs; its default pair is not proof of compatibility.

    Adaptations and routines

    Actuator tests

    IAW ECUs have no output timer: an output stays energised until something turns it off. This workstation owns the deadline and releases on expiry, on disconnect, and if the browser goes away.

    🧪 This drives the simulated motorcycle, not a real one

    Everything on this page changes the bike the workstation is talking to, never the workstation's own behaviour. Seeded faults move the live channels first and only mature into fault memory afterwards, so you can practise reading the data before the code shows up — and watch a code come straight back if you clear it while the cause is still there.

    Comms quality

    The adapter and the wiring are part of the job. These make the simulator behave like a bad connection so the retry, checksum and timeout paths get exercised on purpose.

    Seeded faults

    Each fault changes the physics, and the code it eventually stores is listed with it. Nothing appears in fault memory straight away.

    What a guided test is

    A single actuator pulse is a twitch. A procedure puts the engine in a known state, does one bounded thing, watches the right channels and says what the result means. Observations are ordinary live reads; anything that moves on the bike goes through the same safety gate and the same output deadline as the Service view. The verdict at the end is an interpretation — a place to start looking, not a diagnosis.
