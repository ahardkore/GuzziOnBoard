## Research priorities and boundaries

- The checksum source reports successful image-level comparisons; checksums alone do not identify the ECU, establish complete backups, authorize programming, or satisfy authentication/recovery. CF 450SR and Hunter 350 exceptions must remain explicit.
- VFR1200F and CCM450 research identify useful next investigations. The VFR source describes a candidate five-byte image ID and possible shifted calibrations but leaves discrepancies and incomplete physical integration details. CCM includes reverse-engineered jobs and third-party artifacts. Neither justifies a generic read/write path.
- iKawa 0x04 throttle uses the source calibration, 0x02 yields a boolean, and 0x44 is converted to hours at whole-minute resolution. These are optional candidates and do not feed the safety gate.
- CTX700 table 0x11 is 20 data bytes and D1 is six data bytes in the source. The raw injector value is not fuel consumption: the source requires user calibration for consumption. No cross-model year or ECU assumption is made.

### WRT Garage Honda K-Line research lead (2026-10-31)

[AMQC-WRT-Diagnosis, commit 8b72c7d](https://github.com/abyryn/AMQC-WRT-Diagnosis/tree/8b72c7d444c2171e14b9d1cbe6df4c016b0685dd) lists Indonesian Honda model/year/ECU combinations and claims PGM-FI K-Line support. We added four **model names** (28 model-year combinations) as **read-only diagnostic attempts**: Vario 125 Techno FI 2012–2015, CB150R StreetFire 2012–2021 (two listed ECU numbers), CBR150R FI 2014–2020, and Supra X 125 Helm-In 2014–2020. Catalog notes record the specific listed ECU identifiers; check the market and label before trying.

The source's generic Honda framing calculates a positive-sum checksum and a different length than the negative-sum, five-byte table query implemented here. Its code does not establish that GuzziOnBoard's exact wake-up, table requests, values, or compatibility work on these bikes. These additions have synthetic fake-ECU tests only, no physical motorcycle verification, and do not provide ECU memory reads, programming or tuning. We did not copy that repository's code: its README displays an MIT badge but the repository has no corresponding root license file. No capability is inferred for its Shindengen or 5-baud-only listings.

### K-Line research expansion: AiM, HRC, Kawasaki adapter and KDS2Bluetooth

This pass adds **65 previously uncatalogued model/year combinations across 14 model names**, not 65 new models. These are raw, read-only attempts; their fake-ECU tests do not show a motorcycle or GuzziOnBoard hardware worked.

- [AiM's Suzuki cable listing](https://store.aim-sportline.com/en/others/237-suzuki-sports-bike-dedicated-cable.html) lists GSX-R600 2004–2023 and GSX-R750 2004–2017 for its SDS protocol. Newly covered years use the existing bounded raw SDS attempt, without overriding the more-specific 2011 GSX-R600 profile. AiM's compatibility with its logger does not establish our exact request or response shape. AiM separately lists **SDS 2** for GSX-R1000 2017 onward; we do not apply the older GSX-R profile to those bikes.
- [AiM's CRF guide](https://www.aimtechnologies.com/aim-support/docs/SoloDL_HondaCRF-HDS_250dal2010+450dal2009_100_eng.pdf) describes HDS table 10 over K-Line for CRF 250 models with the PGM-FI setting tool. [Honda HRC](https://www.honda.co.jp/HRC/products/racingkit/crf250r/settingtool/) lists specific CRF250R and CRF250RX generations for its own setting tool. Combined, they support additional *attempts* on CRF250R 2010, 2012 and 2016–2022, and CRF250RX 2019–2022. HRC's tuning tool functionality is not implemented by our raw diagnostic attempt. Its interface and maps vary with year; compatibility with this implementation is unverified.
- A [Kawasaki adapter seller](https://www.amazon.com/AMHTDOL-Diagnostic-Connector-Motorcycles-Compatible/dp/B0GVTYHT94) lists KDS 4-pin 2010–2016 and K-Line 6-pin 2016–2020 model groups. We added bounded model/year selections from those groups, not the Euro 5 CAN group. This is a seller claim about adapters, not a published KDS command or a GuzziOnBoard hardware test. Connector and ECU variations remain important; the selected adapter must match the actual bike.
- [KDS2Bluetooth, GPL-3.0, commit bb8be32](https://github.com/HerrRiebmann/KDS2Bluetooth/tree/bb8be32a6ed54d995c838bb58af528731fc8fae1) reports broad Kawasaki KDS and Suzuki SDS support for its own software, including the Suzuki `21 08` exchange. We added **ECU-only** optional generic Kawasaki and Suzuki research selections for users whose bikes lack a specific catalog entry. These do not claim fitment for any bike. The existing read-only, fixed-address K-Line sessions still require a matching handshake and accept only allowlisted raw diagnostic queries; no fault clearing, memory or programming is enabled. Generic Suzuki reports a bounded 1–60-byte raw snapshot, without a guessed sensor layout. These paths have synthetic tests only and may not work with a particular ECU. No code was copied from KDS2Bluetooth.

### Additional Honda flash research lead

[Josave Tuner, commit 2ac0fdeb](https://github.com/Sirawit45/josave-tuner/tree/2ac0fdeb679736271bf12fe210b578683d092aa2) advertises Keihin and Shindengen Honda K-Line flash read/write and includes source plus simulated tests. Its read path suggests a promising proprietary Honda framing sequence, but its tests explicitly use a virtual ECU; the Shindengen test reads 16 KiB and checks its first 256 bytes, not a complete 512 KiB physical dump. The repository had no top-level license or GitHub license metadata when inspected, so no code or database was copied. Its reader does not check unlock return values or the echoed address before accepting a long-enough reply, and its fallback request truncates the address to 16 bits. These are integration issues to resolve rather than assumptions that a dump is valid. [MCU Innovations' HondaECU FAQ](https://mcuinnovations.com/software/hondaecu/faq/) says its own K-Line flash reading currently covers Keihin only, with additional R8C limitations; that limitation describes MCU's product and does not disprove Josave's separate claim. Neither source establishes this project's flash reader, checksum, recovery or writer for any new bike.
