What it actually does

No decorative features. Everything below is implemented, and what isn't proven on hardware says so.

Real protocol stack

KWP2000 (ISO 14230) application and data-link layer — fast init, 5-baud init, framing, checksums — plus ISO-TP (ISO 15765-2) segmentation for the CAN bikes. Unit tested down to the timing.

A catalog with teeth

10 Marelli ECU families, 118 model variants across Moto Guzzi, Ducati and Aprilia (1992–2026), each with a confidence level that governs what the workstation will let you do. Enforced in code, not in the docs.

A simulator that isn't fake

The simulated ECU speaks the actual wire protocol and drives the whole stack — and a virtual-CAN rehearsal exercises the complete ISO-TP path: segmentation, flow control, reassembly. No bike required.

Identify · live data · fault codes

ECU identification, live channels with proper scaling, DTC read and clear with the workstation-observed context, actuator tests, TPS and adaptation resets — gated by confidence and safety.

Memory: read, verify, back up

ECU memory read with the 5AM path grounded in a verified capture, and backups verified by a second independent read before you're told they're good.

Maps, sessions, reports

TunerPro XDF table rendering and named diffs of two dumps (by table and axis value, not raw offset), session recording and channel-by-channel comparison, text/JSON reports and PDF export.

Safety is the feature

A workstation that commands a motorcycle ECU must know what it doesn't know. Every family in the catalog carries a confidence level — and the level decides what's permitted.

VERIFIED-CAPTURE

Grounded in a real capture

The IAW 5AM / 5AM2 path is anchored to a verified bus capture: full diagnostics and memory read. Writing is implemented and simulator-tested, but stays gated pending bench confirmation.

DOCUMENTED

Documented protocol

Full diagnostics — identification, live data, fault codes, routines — for families whose protocol behavior is documented across the GuzziDiag ecosystem.

INFERRED

Inferred only

Degrades to identification, fault codes and the read-only discovery sweep. The workstation will not command an ECU it does not genuinely understand — including every cross-brand Ducati and Aprilia entry.

Backups you can trust

Two independent reads must agree before a backup is called good; interrupted writes leave checkpoints with recovery guidance.

No fake keys

SecurityAccess seed/key plumbing supports key-provider plugins — but no unverified key algorithm ships as if it worked. The transcribed 5AM key stays hardware-gated.

Careful by construction

Read-only discovery sweeps, adapter pre-flight (including the FTDI latency timer), a connect checklist, and CAN capture analysis that only ever listens.

"Confidence is enforced, not decorative. Anything below documented degrades to identification, fault codes and the read-only discovery sweep." — the rule the whole workstation is built around

Run the real thing

Simulator mode needs nothing but Python 3.11+ — no serial port is opened until you ask for one.

workstation — terminal
# simulator mode: the whole workstation, no bike, no cable
$ python3 run_server.py
#  → open http://127.0.0.1:8000 — pick a bike in the Garage

# real hardware (pyserial + python-can)
$ pip install -e '.[hardware]'
$ python3 run_server.py

Try Griso 1200 8V / 2012 in the Garage, connect in simulator mode, and the rest of the workstation comes alive. TunerPro XDF definitions for the maps view are yours to supply (third-party, see the README) — rendering and diffing are strictly read-only.
