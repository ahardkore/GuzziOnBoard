    ⚠ These actions move things on the motorcycle

    Actuator tests energise real outputs — injectors squirt fuel, coils make sparks, the fuel pump pressurises the rail. Adaptation resets discard learned values and cannot be undone. Every action below shows exactly which preconditions pass and which do not.

    Adaptations and routines

    Actuator tests

    IAW ECUs have no output timer: an output stays energised until something turns it off. This workstation owns the deadline and releases on expiry, on disconnect, and if the browser goes away.

    🧪 This drives the simulated motorcycle, not a real one

    Everything on this page changes the bike the workstation is talking to, never the workstation's own behaviour. Seeded faults move the live channels first and only mature into fault memory afterwards, so you can practise reading the data before the code shows up — and watch a code come straight back if you clear it while the cause is still there.

    CAN identifier discovery

    The CAN-era bikes wrap the same diagnostics in ISO-TP, and the request/response id pair has never been confirmed on one. Capture the bus while another tool (GuzziCanDiag) talks to the bike, then let this find the pair — read-only by construction.

    How to take the capture
    1. Connect a CAN adapter to the bike's OBD socket and your laptop. Nothing else should be talking on the bus.
    2. Start logging — SavvyCAN: connect, File → Log To File, run a GuzziCanDiag session (identify + live data is plenty), stop and export as CSV. socketcan: candump -tz can0 > capture.log.
    3. Analyse the file here. A minute of a live session is enough.

    ECU memory

    Reading an ECU image is slow but safe. Writing one is neither. Everything here is ordered the way it has to happen: check the adapter, read a backup, verify it, validate the new image, and only then write.

    Connect to an ECU first.

    1 · Adapter pre-flight

    A 16 ms FTDI latency timer is the usual reason a 20 minute read takes hours. GuzziDiag calls 1 ms essential.

    Not checked.

    2 · Backup

    A backup is read twice and only kept if both reads agree byte for byte. One read over a noisy K-Line is not a backup.

    3 · Validate an image

    Size, vector table, entropy and hardware family are checked before a single byte is sent. Flashing an HW1xx image into an HW3xx ECU bricks it.

    Maps & tables

    Render a dump as named fuel and ignition tables with a TunerPro XDF definition (the GuzziDiag files live at von-der-salierburg.de). Drop .xdf files into ~/.guzzionboard/xdfs/ — none ship with this project. Strictly read-only.

    4 · Write

    Writing is an opt-in, not a hidden feature. It stays refused until every precondition below is green.

    SecurityAccess key providers

    No verified key algorithm ships with this project for any Guzzi ECU. Drop one into the plugin directory if you have it.
