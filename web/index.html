1 · Motorcycle

Pick the make, model and year; the workstation resolves the ECU and the protocol it speaks. Some models have overlapping ECU fitments within a model year. Verify the label and evidence for the exact motorcycle; a research entry does not enable diagnostics.

Selects the vehicle without opening a diagnostic session. Disconnect any active session first.

Override: pick an ECU family directly

With a selected model and year, only a cataloged matching ECU is accepted and the vehicle confidence still applies. Clear the model for an ECU-only bench selection. The generic OBD-II CAN option is always ECU-only, not a vehicle match.

2 · Connection

For the source-listed Harley or ECU-only J1850 / HarleyDroid profile: enter the paired ELM327 serial port at 38400 baud and select read-only mode. Source reports Harley J1850 bikes, notably Sportster; model/year layouts vary. GuzziOnBoard has not hardware-tested this integration. Adapter setup alone does not identify an ECU.

Use the profile default first. The Honda CB500F DashBle entry is an explicit ECU-only option: its source does not specify the bike year or ECU and the integration is not hardware-tested. Auto waits 2.6 seconds after a failed fast attempt before slow init, so older ECUs do not mistake the fallback for the rest of a partial 5-baud address.

Harley Delphi CAN identity research is available by source-listed vehicle or ECU-only override. This integration has synthetic tests only and may not work for a selected bike. It requires 500 kbit/s and fixed 0x7E0/0x7E8; enter an explicit SocketCAN channel (e.g. can0) or PCAN channel (e.g. PCAN_USBBUS1). This attempts tester-present, five raw identity DIDs and four raw source-observed DIDs; a response does not verify fitment and the source may require authentication. No ECU memory, security, or programming is provided.

Generic OBD-II 11-bit CAN is an explicit ECU-only option, not a claim of compatibility with the selected motorcycle. It needs a compatible CAN interface and correctly wired adapter, 500 kbit/s and a physical OBD ECU ID pair; this integration has not been hardware-tested. It reads supported standard live PIDs and emission-related stored faults, not ECU memory.

Physical MIU G4 and 11MP sessions are blocked before the adapter opens: generic 0x7E0/0x7E8 IDs are not treated as Piaggio protocol evidence. The opt-in generic OBD profile accepts only physical OBD request/response pairs; its default pair is not proof of compatibility.

The simulator is not a demo subset: live data, fault memory, actuator tests, service adaptations, guided tests, discovery sweeps and the complete ECU-memory cycle — backup, validate, flash, verify — all run against it, and every result comes out labelled simulated.

    ⚠ These actions move things on the motorcycle

    Actuator tests energise real outputs — injectors squirt fuel, coils make sparks, the fuel pump pressurises the rail. Adaptation resets discard learned values and cannot be undone. Every action below shows exactly which preconditions pass and which do not.

    Adaptations and routines

    Actuator tests

    IAW ECUs have no output timer: an output stays energised until something turns it off. This workstation owns the deadline and releases on expiry, on disconnect, and if the browser goes away.

    🧪 This drives the simulated motorcycle, not a real one

    Everything on this page changes the bike the workstation is talking to, never the workstation's own behaviour. Seeded faults move the live channels first and only mature into fault memory afterwards, so you can practise reading the data before the code shows up — and watch a code come straight back if you clear it while the cause is still there.

    Engine

    —

    Comms quality

    The adapter and the wiring are part of the job. These make the simulator behave like a bad connection so the retry, checksum and timeout paths get exercised on purpose.

    Seeded faults

    Each fault changes the physics, and the code it eventually stores is listed with it. Nothing appears in fault memory straight away.

    What a guided test is

    A single actuator pulse is a twitch. A procedure puts the engine in a known state, does one bounded thing, watches the right channels and says what the result means. Observations are ordinary live reads; anything that moves on the bike goes through the same safety gate and the same output deadline as the Service view. The verdict at the end is an interpretation — a place to start looking, not a diagnosis.

    Size, vector table, entropy and hardware family are checked before a single byte is sent. Flashing an HW1xx image into an HW3xx ECU bricks it.
    
      
    
        
        
      
    
      
    
    
    

    
    
      
    Maps & tables
    
      
    Render a dump as named fuel and ignition tables with a TunerPro XDF definition — 94 GuzziDiag definitions and one Honda CBR1000RR definition ship bundled. Drop .xdf files into ~/.guzzionboard/xdfs/ to correct or extend them. Rendering and comparison are read-only; the advanced builder below always writes a new file and never changes its source.
    
      
    The chooser is grouped by motorcycle, not by the title the definition's author happened to type: definitions for the ECU family on the bench come first, everything else is listed under the bikes it was published for and marked as not matching. Picking a map from the wrong family does not give slightly wrong numbers — it reads a different calibration layout at the same addresses. A mismatched definition can be viewed, but the builder refuses to use it.

          Offline log overlay & bounded fuel-correction review
          
    Import a CSV containing time, load/RPM, and separately measured and target AFR. When a time column is selected, ECU state is interpolated at the measured-wideband time minus the explicitly configured delay; gaps, unsettled cells, excessive axis rates, and insufficient aligned cell dwell are rejected. Analysis never changes the image and caps proposed fuel changes. Confirm the selected table really controls fuel quantity under the logged conditions.
