## Fixed findings

1. **Base-map replacement lost the original index entry on failure.** Replacement previously removed and published the old entry before validating the new source. It now copies and verifies the replacement before publishing one index update, retaining the superseded base map and restore-point history.
2. **Vault index updates raced between threads/instances.** A shared reentrant lock now serializes in-process read/modify/write transactions. Unique temporary files and atomic replacement prevent partial index publication; flushed temporary files are fsynced before replacement.
3. **Corrupt vault indexes were silently treated as empty.** Unreadable, malformed, or structurally invalid indexes now fail explicitly rather than being overwritten as a new vault.
4. **Repeated restore saves could overwrite artifact sidecars.** Unique artifact names now distinguish saves even when timestamps and image hashes match. The destination image is rehashed before its record is published.
5. **Map edits through different XDF items could overlap.** Logical-cell duplicate detection did not catch aliases or partial byte overlaps. Builds now reject overlapping byte writes, keeping the manifest from claiming edits silently overwritten by a later change.
6. **Malformed HTTP requests could crash handlers or consume unbounded input.** POST handling now validates content lengths, rejects unsupported transfer encoding, limits JSON bodies to 16 MiB, requires object bodies, and rejects malformed encoding and nonstandard NaN/Infinity literals. Rejected requests close the connection so unread bodies cannot be reinterpreted as requests.
7. **Tune builds wrote the binary twice.** The output path is now included in the manifest before the single save.

Regression tests cover failed replacements, failed atomic publication, corrupt indexes, concurrent vault instances, repeated saves, partial-byte aliases, and malformed requests through a real HTTP server.

## Scope and remaining risks

This is a repository/software audit, not certification of physical ECU programming. Existing tests cover protocol, safety, simulator, mapping, packaging and other application modules; targeted manual review focused on the vault, map-edit/build write path and HTTP boundary. No connected motorcycle, serial adapter, or CAN device was available. Skipped tests remain unverified.

- The vault lock protects threads and instances within one process, not multiple independent application processes sharing a vault. Run only one writer against a vault.
- Atomic index publication is a single-file guarantee, not a transaction across the binary and sidecar. Other firmware/metadata save paths still use separate file writes. A filesystem failure may leave an unindexed artifact; no cleanup deletes recovery images.
- Source-copy hashing detects binary changes during copying, but source sidecar and image are not captured as one filesystem snapshot.
- The local HTTP service is not an authenticated remote service. Do not expose it to untrusted networks. Broader authentication/origin controls and per-route schemas remain follow-up hardening work.
- HTTP framing limits are not a complete defense against slow clients or all deeply nested/oversized semantic payloads.
